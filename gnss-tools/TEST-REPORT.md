## 时间模型与关键回归

跨系统换算以连续 TAI 时间轴为中枢，不再依赖闰秒附近的迭代修正。UTC 的 `23:59:60` 通过显式选项表达，避免 JavaScript `Date` 无法保存闰秒标签的问题。

已验证的关键边界：

- GPS `2017-01-01 00:00:17` → UTC `2016-12-31 23:59:60`。
- UTC `2016-12-31 23:59:60` → GPS `2017-01-01 00:00:17`。
- 非真实闰日输入 `23:59:60` 时显示明确错误。
- 周内秒、年积日、四位年份、真实日期及目标系统历元均有输入校验。
- 2024 年逐日往返转换一致。
- 系统差异文案按被转换的历史时刻计算，不套用当前闰秒数。

## SP3 与广播星历回归

- SP3 历元秒保留 8 位小数，`0.001` 与 `0.002` 秒不会被合并。
- 广播星历生成的 SP3 第二行包含真实 GPS 周、周内秒、采样间隔、MJD 和天内秒。
- 亚秒采样间隔不再被四舍五入为整数秒。
- RINEX 3 混合 GPS／BDS、RINEX 2 GPS、Fortran D 指数及负数拼接字段均有测试。
- GLONASS／SBAS 广播星历仍明确属于暂不支持范围，不会静默生成轨道。

## 后续优化建议

1. 增加移动端导航抽屉；当前窄屏只保留品牌、安装和主题入口。
2. 用外部权威样例进一步交叉验证广播星历轨道与钟差，并补充 Galileo、QZSS 的独立样例。
3. 将大型 SP3 解析和广播星历传播移入 Web Worker，避免大文件阻塞界面。
4. 建立闰秒表更新与版本提示机制，便于未来新闰秒公告后的维护。
5. 如必须上架应用商店，可在 PWA 基础上使用 Capacitor 打包；当前交付不是原生 APK／IPA。
